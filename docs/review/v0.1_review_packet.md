# 资金链证审 V0.1 审核交接包

## 1. 审核目标

本轮不是评估产品是否可以投入真实办案，而是判断当前 Vertical Slice 是否已经证明：

1. 项目问题定义和法律责任边界成立；
2. 系统形成了区别于单提示词的实质工作流；
3. 确定性金额与校验核心可靠；
4. 人工复核、来源定位、日志和失败边界可继续扩展；
5. 下一阶段值得投入UI验收、复杂案例和正式评测。

## 4. 重点审核问题

### 法律业务

- 将“犯罪金额认定”收窄为“资金证据覆盖核验”是否合理？
- 日期默认容差前后3日是否适合首版？
- 第三方收款、退款和超额单笔交易的争议处理是否足够谨慎？
- 起诉书、被害人陈述和流水的证据角色区分是否准确？

### 技术与产品

- Claim、Transaction、EvidenceLink、ReviewDecision 是否足以支持下一版本？
- 候选召回条件是否会漏掉常见交易？
- 重复交易和人工金额篡改的阻断是否完整？
- 四页工作台的信息结构是否符合司法审查习惯？
- 当前日志是否足以支持竞赛复核和基线比较？

### 数据安全

- 默认不持久化和账号脱敏是否满足模拟演示阶段？
- 哪些字段在真实试用前必须进一步去标识化或加密？

## 5. 审核时不要误判的事项

- 24项测试不代表真实案件准确率；它们只是规则回归测试。
- DeepSeek模拟测试不代表正式模型效果。
- Streamlit文件通过语法检查不代表界面已经完成浏览器验收。
- D01-D15是开发案例，未来盲测集必须独立建立。
