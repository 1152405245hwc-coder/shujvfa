# 案件内只读工具层（V0.2）

本文说明「智能查询」这一层的契约与边界。它是 `PROJECT_MUST_READ.md` 中
「LLM 负责理解、Python 负责事实和计算、人工负责最终判断」在查询侧的落地。

## 1. 分层

```text
用户问题
  ↓  （仅自然语言查询）LLM 产出「只读查询计划」，最多 4 步
整份计划预校验（未知工具 / 写工具 / 跨案参数 / 非法参数 / 步数上限）
  ↓  任一步不通过 → 整单拒绝，不执行任何一步
本地只读工具执行（复用既有确定性 service）
  ↓
确定性模板渲染答案（只搬运工具返回值里的数字，不加总、不换算、不推断）
```

快捷查询不经过模型：直接给定工具名与参数执行，离线可用、零 API 费用。

## 2. 工具清单与边界

| 工具 | 回答什么 | 明确不做什么 |
| --- | --- | --- |
| `get_case_overview` | 全案主张、指控总额、已确证覆盖、缺口、候选/弱信号/疑似转回笔数与金额、逐主张复核状态、流水去重口径 | 不给出法律结论，不把候选当已确认 |
| `get_claim_detail` | 单条主张原文定位、候选（区分争议阻断）、弱信号（不计入）、决策来源与状态、陈述事实是否可用 | 不替人工决定纳入/排除 |
| `query_transactions` | 按付款人/收款人/账户/日期/金额/风险码/主张查流水 | 名称精确匹配；金额按 canonical 事件去重 |
| `trace_fund_flow` | 从某笔流水或账户出发的后续相关流水 | 只回答「之后有哪些相关流水」，不认定某笔入账的实际用途 |
| `get_evidence_sources` | 主张原文、流水原始行、第三方账户事实、材料提及，含定位 | 不把「材料里出现过这个名字」当作证明 |
| `get_open_review_items` | 未处置候选、弱信号、陈述矛盾、跨主张风险、调查回查事项、待确认别名 | 不把系统建议算作已人工处置 |

写操作（纳入 / 排除 / 列为争议 / 确认别名 / 签署 / 删除）**不开放给模型**，仍由人工在界面点击。

## 3. 关键口径

- **金额**：全部为两位小数字符串，来源为既有确定性 service；工具不重算。`query_transactions`
  的合计按 canonical 事件去重（镜像流水只计一次），并在 `sum_basis` 中写明口径。
- **候选 / 弱信号 / 人工确认**：三者分别呈现。弱信号（如他人代付）永不计入金额；
  只有人工签署的处置才减少待办。
- **账户身份**：链路追踪只按精确账户号或账户标识连接，绝不按姓名连接；已脱敏账号
  （`****0123`）不构成身份，不参与连接，避免凭可见后缀伪造链路。
- **来源层级**：`is_proof` 一律为 `False`，另用 `assertion_level` 与 `proves` 说明每项来源
  实际能支持什么。原文定位只证明「该材料确有这段记载」，不证明付款事实成立。
- **时间**：链路只允许严格向后；同日缺时间的流水标注 `ordering=unordered`、
  `ordering_basis=same_day_without_time`，不伪作确定顺序。
- **资金混同**：`commingling_boundary` 标注账户同时存在其他收付，`boundary_note` 明确说明
  不能据链路认定特定款项归属。

## 4. 查询记录

每次查询返回 `answer` / `results` / `audit` / `mode` / `warnings`。`audit` 含工具名、脱敏后的
参数、结果哈希、耗时与时间。记录只存在于本次会话返回值中，可下载，**不写入案件签署审计或
数据库**；浏览器刷新不恢复旧答案。案件材料、复核版本或当前选择变化后旧答案失效。

## 5. 未做的部分（有意）

- 不做无限 Agent Loop：最多 4 步静态只读计划，便于审计、避免行为漂移。
- V1 不做二次 LLM 解释：模板渲染的每个数字都能在工具结果中逐字找到；若将来引入模型解释，
  必须约束为只能引用已存在的 fact，且不得生成新数字。
- 不引入外部法律检索、向量库或 Agent 框架；材料检索目前为有界关键词/实体定位。
