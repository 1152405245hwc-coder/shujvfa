# V0.1 实际完成状态

日期：2026-08-28
状态：V0.1 MVP core frozen

## 已实现并离线验证

- 固定TXT/CSV输入和虚构演示案件；
- Mock、OpenAI及DeepSeek结构化Claim提取接口；
- 模型来源原文防伪校验；
- 被害人陈述金额、日期、收款人冲突检测；
- CSV标准化、Decimal金额和来源行定位；
- 候选交易匹配、重复流水检测和风险代码；
- `INCLUDED / EXCLUDED / DISPUTED` 人工处置；
- Claim 保持 `model_extracted`，必须经显式人工确认后才能进入交易复核；
- 所有候选必须逐笔处置，并记录固定 reason code 和可选备注；
- disposition 与 reason code 必须属于允许的合法组合；
- Claim 原文片段及字符位置保留到工作流和报告；
- 账户冲突风险不会再被姓名匹配掩盖；
- 五状态Claim汇总和Verification Engine；
- v1、v2、v3连续决定版本；
- JSON、CSV、HTML脱敏报告；
- SQLite Claim、Transaction 和 Decision 均禁止同 ID 不同内容静默覆盖；
- SQLite 只在 Claim 经人工确认后首次保存 Claim；
- 人工决定的父版本必须属于同一案件和同一 Claim；
- `human_review`、`verification` 及失败步骤日志；
- 单 Claim 限制明确，0项或多项提取不会静默丢失；
- 41项自动化测试、3项参数化子测试及 CLI 端到端演示通过；
- G01-G05公开虚构Gold Cases及机器可读预期已冻结；
- Mock baseline 5/5案例、45/45检查通过，格式与来源引用通过率均为100%，重复运行一致；
- DeepSeek在同一五案上5/5案例、45/45检查通过，格式与来源引用通过率均为100%。
- H01-H05内部留出集在首次真实调用前完成SHA-256封存，Mock和DeepSeek均为5/5案例、
  45/45检查通过；DeepSeek总计827输入/469输出tokens，平均延迟922.8ms。
