# V0.1 实际完成状态

日期：2026-08-27  
状态：V0.1 MVP runtime candidate

## 已实现并离线验证

- 固定TXT/CSV输入和虚构演示案件；
- Mock及DeepSeek结构化Claim提取接口；
- 模型来源原文防伪校验；
- 被害人陈述金额、日期、收款人冲突检测；
- CSV标准化、Decimal金额和来源行定位；
- 候选交易匹配、重复流水检测和风险代码；
- `INCLUDED / EXCLUDED / DISPUTED` 人工处置；
- Claim 保持 `model_extracted`，必须经显式人工确认后才能进入交易复核；
- 所有候选必须逐笔处置，并记录固定 reason code 和可选备注；
- Claim 原文片段及字符位置保留到工作流和报告；
- 账户冲突风险不会再被姓名匹配掩盖；
- 五状态Claim汇总和Verification Engine；
- v1、v2、v3连续决定版本；
- JSON、CSV、HTML脱敏报告；
- SQLite Claim、Transaction 和 Decision 均禁止同 ID 不同内容静默覆盖；
- `human_review`、`verification` 及失败步骤日志；
- 单 Claim 限制明确，0项或多项提取不会静默丢失；
- 31项自动化测试及 CLI 端到端演示通过。

## 运行验收结果

- Streamlit 1.62 已安装，四页工作台完成实际浏览器交互验收；
- Mock Demo 从材料输入运行到 `PARTIALLY_CORROBORATED` 报告，覆盖30,000元、未覆盖20,000元；
- Claim 原文可查看，未确认时不能进入交易复核；
- `PENDING` 候选会阻止提交，逐笔 `INCLUDED + MATCHED_CLAIM` 可生成 v2；
- 流水页账号保持末四位脱敏并显示 CSV 来源行；
- JSON、CSV、HTML 均实际触发下载，下载内容包含逐笔理由、来源行和脱敏账号；
- 运行日志显示 `human_review` 和 `verification`，最终页面无 traceback 或浏览器控制台错误；
- DeepSeek请求及响应解析已用模拟HTTP响应测试，未使用正式API Key进行真实调用；
- pytest 已安装并实际执行，结果为 `31 passed`。
