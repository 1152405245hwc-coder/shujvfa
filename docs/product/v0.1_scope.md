# V0.1 产品范围与责任边界

状态：待团队确认  
版本：0.1.0  
适用实现：Vertical Slice V0.1

## 1. 产品定义

“资金链证审”V0.1 是面向刑事审判人员的案件审查辅助工具。它围绕诈骗类案件中的
一项具体任务运行：将起诉书中的被害人付款指控，与被害人陈述和银行交易流水逐项对应，
形成资金证据覆盖情况、矛盾、缺口和人工复核记录。

系统回答的是：

> 当前导入的资金及陈述证据，在多大范围内与起诉书中的付款指控相互对应？

系统不回答的是：

> 被告人是否构成诈骗罪，以及依法应认定的最终犯罪金额是多少？

## 2. 目标用户

V0.1 的主要用户是审理诈骗类刑事案件的法官、法官助理及其他经授权的司法工作人员。
律师、检察人员和民事案件使用者属于后续可能扩展的用户，不作为 V0.1 验收对象。

## 3. 核心工作单元

系统的最小审查单元是 `PaymentClaim`：材料中关于“一名被害人在一定时间范围内，
向特定收款对象支付特定金额”的事实主张。

每个 `PaymentClaim` 独立完成：

1. 提取事实主张及原文位置。
2. 从流水中召回候选交易。
3. 展示支持、冲突和缺失信息。
4. 由人工逐笔决定纳入、排除、争议或暂缓。
5. 确定性计算证据覆盖金额和未覆盖金额。
6. 生成保留来源及版本的复核结论。

案件级金额只允许由已确认的 `PaymentClaim` 汇总产生，不得直接由模型生成。

## 4. V0.1 输入

| 材料 | 格式 | 作用 | 是否必需 |
| --- | --- | --- | --- |
| 起诉书节选 | UTF-8 `.txt` | 提取付款指控 | 是 |
| 被害人陈述 | UTF-8 `.txt` | 提供付款陈述及交叉核对 | 是 |
| 银行流水 | 固定字段 UTF-8 `.csv` | 提供客观交易记录 | 是 |

流水字段固定为：

```text
transaction_id,date,time,payer,payer_account,payee,payee_account,amount,remark
```

V0.1 仅接受人民币，金额精确到分。账户号在界面和日志中默认脱敏，只显示末四位。

## 5. V0.1 输出

系统必须提供：

- 指控事实清单及材料来源定位；
- 标准化交易清单及 CSV 原始行号；
- 每项指控的候选交易及字段匹配说明；
- 人工逐笔复核结果、理由和备注；
- 资金证据覆盖金额、未覆盖金额及争议金额；
- 矛盾、重复、缺失和解析异常提示；
- 系统建议与人工复核的版本链；
- JSON、CSV 和可打印 HTML 审查底稿；
- 不含隐性思维过程的关键运行日志。

所有页面和报告必须持续显示：

> 本结果仅反映当前导入材料的资金证据对应与覆盖情况，不替代办案人员对证据能力、
> 证明力、犯罪构成及犯罪金额作出的最终判断。

## 6. 明确不做

V0.1 不实现：

- 自动认定犯罪成立、主观故意或非法占有目的；
- 自动给出最终犯罪金额、量刑建议或裁判结论；
- PDF、Word、图片、扫描件、微信或支付宝截图解析；
- OCR、复杂表格识别或手写内容识别；
- 多层账户穿透、资金去向追踪或团伙关系图谱；
- 法律规范向量检索、复杂 RAG、Neo4j、LangGraph 或多智能体；
- 民事案件、合同纠纷或执行案件流程；
- 用户权限、互联网部署和真实案件云端传输。

## 7. 人机责任边界

### 系统可以自动完成

- 材料结构化提取；
- 交易格式校验、标准化、去重和候选召回；
- 已纳入交易的确定性金额计算；
- 数据引用、版本及一致性校验；
- 风险提示和审查底稿生成。

### 必须由人工完成

- 确认材料提取结果；
- 决定每笔候选交易是否纳入某项指控；
- 处理第三方账户、退款、矛盾陈述等需要专业判断的情形；
- 确认审查版本；
- 作出最终证据评价、事实认定和法律判断。

系统不得把模型输出直接写成 `HUMAN_CONFIRMED`，也不得覆盖历史人工决定。

## 8. 完整工作流

```text
创建案件
  -> 上传并登记三类材料
  -> 提取并人工确认 PaymentClaim
  -> 解析、标准化和去重 Transaction
  -> 为每项 PaymentClaim 召回 CandidateMatch
  -> 逐笔人工复核 CandidateMatch
  -> 汇总资金证据覆盖状态
  -> 执行 Verification
  -> 生成不可覆盖的新版本 ReviewDecision
  -> 导出审查底稿和运行日志
```

任一严重校验错误都必须阻止人工确认和正式报告导出，但允许导出带错误标识的诊断数据。

## 9. V0.1 完成定义

V0.1 只有同时满足以下条件才算完成：

1. 在全新本地环境中按照 README 可以启动。
2. Mock 模式不联网即可跑通完整流程。
3. 演示案件 D01-D10 全部达到预期结果。
4. 单元和端到端测试全部通过。
5. 所有金额均可追溯到已确认交易及 CSV 行号。
6. 任何无交易支撑的手工金额修改都无法通过校验。
7. 系统建议、人工决定、错误和模型调用均有日志。
8. 不含真实个人信息、API 密钥或真实案件材料。

## 10. 后续版本候选

通过 V0.1 后，按风险逐步增加：多被害人和多项指控、拆分或合并付款、第三方收款、
退款与返还、Excel 导入、PDF 文本层、有限 OCR、账户关系和评测集扩充。
