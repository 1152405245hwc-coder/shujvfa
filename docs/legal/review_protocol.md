# V0.1 资金证据审查协议

状态：待司法实践口径确认  
版本：0.1.0

## 1. 协议目的

本协议把资金证据审查过程转化为可运行、可校验的规则。它只规范“材料之间是否对应”及
“当前资金证据覆盖多少指控金额”，不规定犯罪构成、证据采信或最终犯罪金额。

系统使用的“支持”一词均指“资金证据对应支持”，不得解释为对全部待证事实的证明。

## 2. 证据角色

| 材料 | 系统角色 | 限制 |
| --- | --- | --- |
| 起诉书 | 指控事实来源 | 不能作为证明自身真实性的独立证据 |
| 被害人陈述 | 付款事实陈述来源 | 需要与流水及其他材料交叉核对 |
| 银行流水 | 客观交易记录来源 | 只能证明交易记录本身，不能单独证明诈骗性质 |
| 人工复核记录 | 程序性审查意见 | 不替代司法裁判结论 |

## 3. 审查对象与前置条件

一项 `PaymentClaim` 至少包含：被害人、指控金额、起止日期、来源证据和原文位置。
缺少被害人、金额或来源定位时进入 `EXTRACTION_REVIEW_REQUIRED`，不得自动匹配。

交易进入候选集前必须：

- 金额可解析为大于零的人民币 `Decimal`；
- 日期合法；
- 付款方或付款账户至少存在一项；
- 收款方或收款账户至少存在一项；
- 原始证据 ID 和 CSV 行号完整；
- 通过导入内重复检查。

## 4. 机器候选召回规则

候选召回应偏向高召回率，不能直接决定纳入。每个候选必须给出命中的规则、字段差异和
可供人工检查的原始数据。

| 编号 | 规则 | 系统动作 |
| --- | --- | --- |
| M01 | 付款账户相同 | 强匹配信号 |
| M02 | 付款人标准化姓名相同 | 中匹配信号；不得覆盖账户冲突 |
| M03 | 收款账户相同 | 强匹配信号 |
| M04 | 收款人标准化姓名相同 | 中匹配信号；不得覆盖账户冲突 |
| M05 | 交易日期处于指控日期范围 | 强时间信号 |
| M06 | 日期在范围前后允许窗口内 | 弱时间信号并提示偏差；默认窗口 3 日 |
| M07 | 单笔金额等于指控金额 | 金额信号，不足以单独纳入 |
| M08 | 单笔金额小于指控金额 | 允许作为拆分付款候选 |
| M09 | 单笔金额大于指控金额 | 召回但标记 `AMOUNT_EXCEEDS_CLAIM` |
| M10 | 同额但人物、账户均不匹配 | 不因同额自动召回；若人工搜索发现则标记弱候选 |

V0.1 自动候选最低条件是：付款侧至少一项匹配，并且日期命中 M05/M06。收款侧完全不匹配、
金额异常或存在字段冲突时仍可展示，但必须标记风险，不能自动纳入。

## 5. 人工逐笔处置状态

每笔候选交易相对于一项 `PaymentClaim` 只能处于以下状态之一：

| 状态 | 含义 | 是否计入覆盖金额 |
| --- | --- | --- |
| `PENDING` | 尚未复核 | 否 |
| `INCLUDED` | 人工确认与该指控对应 | 是 |
| `EXCLUDED` | 人工确认不属于该指控 | 否 |
| `DISPUTED` | 材料冲突或需要进一步判断 | 否，单列争议金额 |

`INCLUDED`、`EXCLUDED`、`DISPUTED` 必须记录操作者、时间、理由代码和可选备注。
人工可以改变机器建议，但不能删除机器建议及此前版本。

## 6. 处置规则

| 编号 | 情形 | V0.1 处理 |
| --- | --- | --- |
| R01 | 姓名、账户、日期、金额均一致 | 建议 `INCLUDED`，仍需人工确认 |
| R02 | 同一被害人拆分为多笔支付 | 可分别 `INCLUDED`，汇总额不得超过无解释的指控金额 |
| R03 | 一笔交易可能对应多项指控 | 标记 `CROSS_CLAIM_DUPLICATION`，确认前禁止重复计入 |
| R04 | 完全相同流水被重复导入 | 保留一条规范交易，其余标记重复且不得计入 |
| R05 | 流水交易 ID 不同但关键字段相同 | 标记疑似重复，必须人工判断 |
| R06 | 付款人姓名一致但付款账户不同 | 允许候选；必须确认账户主体关系后才能纳入 |
| R07 | 收款人为第三方或名称不一致 | 进入 `DISPUTED`；V0.1 不自动判断代收关系 |
| R08 | 付款日期超出允许窗口 | 不自动召回；人工检索加入后默认为 `DISPUTED` |
| R09 | 交易金额大于该项指控金额 | 不得部分切割交易自动计入，默认为 `DISPUTED` |
| R10 | 存在退款或返还记录 | 原付款与退款分别保留；V0.1 不自动从犯罪金额扣减 |
| R11 | 起诉书与被害人陈述金额矛盾 | Claim 标记冲突，禁止形成“完全覆盖”结论 |
| R12 | 只有陈述、未找到流水 | 输出资金证据未覆盖，不得输出事实不存在 |
| R13 | 只有流水、无对应指控 | 作为未关联交易展示，不计入任何 Claim |
| R14 | 备注内容与指控用途一致或不一致 | 仅作提示信号，不单独决定纳入或排除 |
| R15 | 人工调整总额但未选择对应交易 | 校验失败，禁止确认 |

## 7. Claim 汇总状态

汇总只使用人工 `INCLUDED` 的交易。定义：

```text
covered_amount = sum(unique included transaction amounts)
uncovered_amount = max(claimed_amount - covered_amount, 0)
disputed_amount = sum(unique disputed transaction amounts)
```

不得使用浮点数，不得让模型计算金额。状态优先级如下：

1. `CONFLICTING`：材料存在尚未解决的实质金额、主体或重复计入冲突。
2. `PENDING_REVIEW`：存在候选交易尚未人工处置，或提取结果尚未确认。
3. `FULLY_CORROBORATED`：无实质冲突，`covered_amount == claimed_amount`。
4. `PARTIALLY_CORROBORATED`：无实质冲突，且 `0 < covered_amount < claimed_amount`。
5. `UNSUPPORTED`：无实质冲突，且 `covered_amount == 0`。

若 `covered_amount > claimed_amount`，必须产生 `OVER_COVERED_AMOUNT` 校验错误，不能生成正式状态。

## 8. 案件级汇总

案件级指控金额等于经人工确认的各 `PaymentClaim.claimed_amount` 之和。案件级覆盖金额等于
所有 Claim 下唯一 `INCLUDED` 交易的金额之和。同一规范交易不得跨 Claim 重复计算。

只要任一 Claim 处于 `CONFLICTING`、`PENDING_REVIEW` 或校验错误状态，案件不得显示为
“审查完成”，只能显示“部分完成”或“需处理”。

## 9. 强制校验

| 编号 | 校验 | 失败级别 |
| --- | --- | --- |
| V001 | 所有金额可由 `Decimal` 精确重算 | 阻断 |
| V002 | 每个引用的 Claim 和 Transaction 存在 | 阻断 |
| V003 | 同一 Claim 不重复计入规范交易 | 阻断 |
| V004 | Claim 有有效来源证据及位置 | 阻断 |
| V005 | Transaction 有有效来源证据及 CSV 行号 | 阻断 |
| V006 | 所有 EvidenceLink 两端对象存在 | 阻断 |
| V007 | 覆盖金额等于唯一 INCLUDED 交易金额之和 | 阻断 |
| V008 | 未覆盖金额计算正确且不小于零 | 阻断 |
| V009 | 同一交易未跨 Claim 重复计入 | 阻断 |
| V010 | 所有人工决定均有操作者、时间和理由 | 阻断 |
| V011 | 人工确认版本指向其前一系统建议版本 | 阻断 |
| V012 | 存在材料冲突时未错误标记为完全覆盖 | 阻断 |
| V013 | 账户号在展示与日志中已脱敏 | 阻断导出 |
| V014 | 输入文件哈希与证据登记一致 | 阻断 |

任何阻断错误都禁止创建 `HUMAN_CONFIRMED` 版本。

## 10. 版本与审计

系统首次生成 `SYSTEM_PROPOSED` 决定。人工操作产生新的 `HUMAN_CONFIRMED` 或
`HUMAN_REJECTED` 决定，并通过 `supersedes_decision_id` 指向上一版本。

日志记录任务编号、案件编号、步骤、工具或模型、提示词版本、开始与结束时间、耗时、
输入输出哈希、Token 统计、结果和异常。日志不得记录隐性思维过程、完整账户号或不必要的原文。

## 11. 报告措辞

允许使用：

- “已找到与该项指控对应并经人工纳入的流水共计……”
- “当前资金证据覆盖金额为……”
- “尚有……未发现对应流水，建议进一步核查。”
- “该交易存在第三方收款或材料冲突，需人工判断。”

禁止使用：

- “犯罪金额认定为……”
- “被告人已经构成诈骗罪。”
- “该流水证明被告人具有非法占有目的。”
- “未找到流水，因此该项指控不成立。”

## 12. 待团队确认的法律业务问题

以下问题不阻止 V0.1 确定性核心开发，但进入 V0.2 前必须由团队结合真实办案流程确认：

1. 默认日期窗口是否应固定为 3 日，还是只允许案件级人工配置。
2. 对大于指控金额的单笔交易，是否允许人工拆分“本项关联金额”。
3. 退款在何种条件下进入资金事实层、证据层或法律认定层的不同计算。
4. 第三方收款需要哪些材料才能从 `DISPUTED` 转为 `INCLUDED`。
5. 同一被害人多份陈述的冲突解决和证据版本规则。
